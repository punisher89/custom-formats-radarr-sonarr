# Russian Custom Formats — Dub Priority v2 (test branch)

⚠️ **Экспериментальная конфигурация.** Ветка `test/dub-priority-v2` не затрагивает `main`.
Используйте **только один набор** CF в каждом приложении, создайте резервную копию Quality Profiles перед импортом.

## Основные отличия v2
- Отдельное слово `DUB` больше **не является доказательством русского языка**. Остаются явные `RUS DUB`, `RUSSIAN AUDIO`, `RU AUDIO`, русский текст и ограниченный список узнаваемых русскоязычных команд.
- Подсказка по студии **не назначает автоматически тип перевода «дубляж»**. Для +1000 нужен явный маркер перевода. Студия даёт только +75.
- Бонусы +100 за **явно подписанный** официальный/лицензионный дубляж и −150 за **явно подписанный** любительский/fandub; без угадывания правового статуса по студии.
- Одноголосый AVO распознаётся отдельно.
- DV-only WEB-DL/WEBRip без явно указанного HDR получает −20000 (с исключением Hulu), обычный DV HDR10 или Blu-ray не штрафуется.
- Списки Radarr/Sonarr синхронизированы. Аниме-студии не используются как RU fallback.

Прочие технические оценки см. в [scores.csv](scores.csv).

### Порог и порядок качества
- **Minimum Custom Format Score: 10000**. Это работает как практический *порог положительных баллов*, а не как настоящая проверка MediaInfo. Непомеченный иностранный DUB не добирает до порога.
- **Allow Upgrades: включить**.
- **Upgrade Until Custom Format Score: 12000** как отправная настройка для тестирования: порог выше текущих обычных максимальных оценок (~11–12 тыс.). Если хотите постоянного поиска лучших вариантов, используйте значение выше реально достижимой суммы баллов; проверяйте обновления.
- **2160p против 1080p**: ранжирование качества может обогнать CF-баллы. Если дубляж должен быть важнее разрешения, настройте отдельные Quality Profiles или согласованное группирование качеств.
- DV-only WEB отрицательный балл ориентирован на **устройства с проблемами воспроизведения DV**. Если на всех клиентах полноценная поддержка DV без HDR fallback, отключайте этот штраф в профиле.

### Ограничения
- CF читают **заголовок релиза и данные парсера**, а не фактические аудиодорожки. Название студии может совпасть с другим переводом; для уверенности нужен MediaInfo после загрузки.
- «Официальный»/«любительский» определяется **только явным текстовым маркером**. Не является установлением лицензии.
- Специальная проверка DV базируется на явно написанном `HDR`/`HDR10`, а не на анализе видео-потока. Неполные release titles могут приводить к ложным штрафам.
- Названия одного релиза могут содержать несколько аудиодорожек и типов перевода; их независимые CF могут одновременно получить баллы. Тестируйте на своём индексаторе.

## Установка
1. Создайте копию профиля качества Radarr/Sonarr.
2. Импортируйте JSON из `Radarr` либо `Sonarr` через `Settings → Custom Formats → Import`; замените существующие форматы по имени, если потребуется.
3. Установите оценки из [scores.csv](scores.csv) в **Quality Profile**, отдельно для каждой службы; импорт JSON сам по себе не назначает баллы.
4. Убедитесь, что нужные качества (1080p/2160p) активированы.
5. На странице Interactive Search проверьте примеры дубляжа, MVO, немецкого DUB и DV.

## Проверки без дополнительных зависимостей
Нужен Node.js 20+:
```bash
node scripts/validate-formats.mjs
node --test tests/dub-priority.test.mjs
```
Команды выполнять из **корня репозитория**. CI запускает те же проверки для PR и коммитов тестовой ветки.

## План безопасного внедрения
Проверить на десятках реальных заголовков из ваших индексаторов, сравнить результат в Interactive Search, затем пробовать на временных Quality Profiles. В `main` ничего не переносится автоматически.

## Безопасная синхронизация оценок через API
Сначала импортируйте **все** JSON Custom Formats через интерфейс, затем проверьте изменения в режиме просмотра.
Скрипт обновляет **только баллы существующих CF** в **одном выбранном Quality Profile**; сами форматы, индексы, загрузки и другие профили не меняет.
Отсутствие хотя бы одного формата блокирует применение, чтобы избежать частичного обновления.

```bash
# Windows PowerShell:
$env:RADARR_API_KEY="YOUR_API_KEY"
node scripts/sync-scores.mjs --service=radarr --url=http://localhost:7878 --profile="Мой 4K"
node scripts/sync-scores.mjs --service=radarr --url=http://localhost:7878 --profile="Мой 4K" --apply

# Для Sonarr используйте SONARR_API_KEY и --service=sonarr
```

**Без `--apply` скрипт ничего не записывает.** Не выкладывайте API-ключи в GitHub.
Параметры Minimum CF Score, Upgrade Until Score, Quality Order и разрешения профиля необходимо настроить отдельно.
